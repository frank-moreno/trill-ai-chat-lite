## Pre-flight checklist (run in Local + testserver before touching SVN)

- [ ] **Backend deployed first** — `/v1/trial/rotate` live on api-v2.trillai.io (done 2026-07-16 per Francisco). The plugin must NEVER ship before the backend.
- [ ] `php -l` clean on all changed files (no PHP in the assistant sandbox — run locally)
- [ ] Smokes green: `wp eval-file tests/Lite/RotationSmoke.php`, `tests/Content/SearchE2ESmoke.php`, `tests/Search/ProductSearchSmoke.php`
- [ ] **THE gate — E2E reinstall on the testserver:** working chat → delete plugin → reinstall 2.3.0 ZIP → activate → visit any wp-admin page (the post-activation redirect suffices) → chat works WITHOUT touching the backend DB. Logs show `deferring rotation until after activation` (activation request) then `register duplicate → attempting secret rotation → rotated secret stored` (admin_init) and `trial_register_duplicate → trial_rotate... → trial_secret_rotated` (pm2). Note: with WP-CLI activation there is no admin redirect — rotation happens on the first wp-admin load or first chat message (lazy fallback)
- [ ] E2E chat-quality on the testserver (new conversations each): "what is your refund policy?" → Refund page in content-search titles; "what products do you have?" → Trill Cloud product card; nonsense query → no raw URLs in the reply
- [ ] Clean-install regression: fresh site → activate → normal register 201 (no rotation attempted), no notices with `WP_DEBUG` on
- [ ] Upgrade path: install 2.2.2 ZIP → use widget → update to 2.3.0 ZIP → chat keeps working with the SAME secret (no re-register, no rotation)
- [ ] Plugin Check against the **built ZIP**, not the working copy
- [ ] `wp i18n make-pot . languages/trill-ai-chat-lite.pot` re-run (new strings: rotate errors, failure notice)
